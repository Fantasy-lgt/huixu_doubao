### Description

按简报六步写清楚"为什么做、给谁做、约束是什么、参考什么"，后续设计与开发都回到这页对口径。

**1. 产品目标（做什么、为什么）**

把初代本机版「汇序 v0.1」演进为云端账号版**个人汇报材料工作台**：用户沉淀个人材料库，用表单或一句话指令触发整理，得到结构完整、出处可核对的汇报初稿，选择模板卡片后导出可编辑 PPTX，并支持跨期追溯与年度汇总。
双重目标：①验证"材料沉淀 + 模板复用 + 溯源整理"能否减少汇报整理成本；②产出一份架构清晰、可部署演示、能讲清取舍的求职作品集。

**2. 目标市场与用户**

- 首要人群：中小企业行政/综合/人力/内勤岗、项目助理、销售内勤——定期写月报、管理会汇报、总结，材料分散、有固定格式要求。
- 次要人群：个人求职者沉淀项目材料与汇报作品集；学生课程汇报/答辩。
- 本期不面向：团队协作场景、企业采购客户、付费会员用户。
- 当前用户样本：1 位制造业综合部受访者（行政/人力/信息岗背景），W2 补访并争取第 2 位。

**3. 约束条件（硬边界，设计不能突破）**

- 时间：8 周（2026-11-02 至 2026-12-27），P0 全量 + 指定 P1 子集。
- 人力：单人全流程（产品/设计/开发/测试/部署），无设计专职、无后端协作。
- 预算：复用已有服务器，不采购高配资源；不接支付、不投入商业化运营成本。
- 技术：贴合既有经验（Vue3 + Node + PostgreSQL + pptxgenjs + SSE）；不把 RAG、Agent 编排、模型微调、多模型复杂编排背进主线。
- 隐私：真实内部资料不外发；外发模型前必须明示确认；密钥不明文落库。
- 范围红线：不做团队协作、不承诺任意母版无损套版、不做自由无限画布、不做行业经营诊断、不做模型训练与自动外发。

**4. 背景与历史（从哪来）**

初代 v0.1 已在本机跑通完整闭环：选期间 → 导入纯文本材料 → 本地规则归集为"重点进展/问题风险/下期计划"三章节初稿 → 来源逐字引用校验 → 人工确认 → 导出 pptx；并具备乐观锁、原子写、外发确认、失败保原稿、21+ 项自动测试等防护。缺口：无账号无数据库、无 AI 真实联调、无模板库、编辑器简陋、无年度实体表。本次演进在复用业务内核的前提下补地基、补 AI、补模板、补体验。

**5. 期望的设计要素（产品形态要求）**

- 交互：飞书式三栏布局（导航 / 主编辑区 / 上下文栏）+ 显性五步工作流，步骤状态可见；不做自由画布。
- 模板：模板卡片 + 规则匹配 Top3；卡片含页型、要点数、场景标签、主色；切换可预览。
- 生成：本地规则模式为默认兜底，AI 为可选增强；AI 输出必须带来源引用或"待补充"标记。
- 反馈：空/加载/错误/无权限状态齐全；关键操作有确认与失败恢复。
- 视觉：轻量后台风格，信息层级优先，不做视觉炫技；组件库先选一个不更换。

**6. 参考材料**

- 初代项目源码与 docs（只读）：需求简报 00、PRD 02、架构合同 04、验收 07。
- 竞品：WPS AI、Kimi PPT、Gamma、讯飞智文（方案第 10 节摘要 + 附录 B 链接）。
- 4 段访谈聊天记录（attachments/img1–4.jpg）。
- 待补：脱敏成品 PPTX、原材料样例、真实模板页型清单。

## 方法卡 3 · Hypothesis Canvas（假设画布）

> **Metadata**

> - Start: 2026-10-31 · Deadline: 2026-11-08（首轮验证）

### Description

四象限结构：左上问题澄清、右上现状成因、左下方案假设、右下验证计划。先把"我们以为成立"的判断摆上台，逐条配验证方法与证伪处理，避免开发到一半才发现前提错了。

#### 象限一 · 左上：问题澄清（我们在解决什么问题）

- P1：定期汇报场景下，材料分散、格式固定、反复套模板，整理过程重复且费时。
- P2：通用 AI PPT 工具强在主题生成，弱在个人历史材料沉淀、来源可溯和既有格式复用。
- P3：单机工具无法跨设备使用、无多账号隔离，且真实 AI 未联调，价值未被使用过的人验证。

#### 象限二 · 右上：现状成因（为什么现有做法不顺畅）

- C1：材料产生于多个来源（聊天、文件、会议记录），缺少统一归集处，月底重新翻找。
- C2：单位/个人有固定模板要求，通用生成结果"不好套"，用户自己要二次排版。
- C3：纯文本 AI 外发有资料外泄顾虑，用户需要可控的发送范围与来源可查。
- C4：年度汇总依赖逐月翻记录，缺少按实体（人/客户/合同）的确定性归集。

#### 象限三 · 左下：方案假设（我们认为怎么解决）

| 编号 | 假设陈述 | 对应象限依据 |
| --- | --- | --- |
| H1 | 整理耗时主要花在"归集旧材料 + 套格式"，而非从零写作；材料库 + 模板复用能压缩这部分 | P1 / C1 / C2 |
| H2 | 目标用户优先要"套用自己的格式体系"，对花哨通用版式的偏好较弱 | P2 / C2 |
| H3 | 用户接受"自带 Key + 本地兜底模式"：无 Key 能用本地规则，有 Key 才调外部模型，外发前明示 | P3 / C3 |
| H4 | 每条内容带原文出处，能降低用户核对成本、提升对生成结果的信任 | P2 / C3 |
| H5 | 对作品集而言，完整工程闭环与清晰取舍记录比功能数量更有面试说服力 | P3 |
| H6 | 技术可行：pptxgenjs 服务端稳定出图；DeepSeek 等 OpenAI 兼容协议对接成本低；标签规则匹配可满足版式推荐 | P1 / P2 |
| H7 | 单人 8 周可完成 P0 全量 + 指定 P1 子集，前提是范围不蔓延、每周投入时间充足 | P3 |

#### 象限四 · 右下：验证计划与证伪处理

| 假设 | 验证方法 | 时点 | 通过标准（宽松，避免数字承诺） | 证伪 / 不通过怎么办 |
| --- | --- | --- | --- | --- |
| H1 | 受访者补访 + 本人手工做一次月报并计时，对比工具链路步骤 | W1–W2 | 用户口述耗时与归集/排版环节吻合；走查时能明显省去找材料动作 | 若主要耗时在写作内容，产品重心从材料库转向写作辅助条目，方案 5.1/5.2 比例调整 |
| H2 | 补访中对比"套用固定模板"与"全新美观版式"的偏好；观察模板匹配使用频次 | W2、W6 | 用户优先选择已有模板卡；匹配功能被实际使用 | 若偏好通用美观版式，模板卡简化为封面+标题样式，减少内置页型投入 |
| H3 | W4 联调时记录 Key 配置完成率；补访询问外发顾虑边界 | W4 | 功能可跑通；用户理解本地/AI 两种模式区别 | 接受度低则不推公共额度（本期不做），强化本地模式与脱敏说明 |
| H4 | W3/W6 可用性走查，观察用户是否点开来源核对、是否提出无出处疑问 | W3、W6 | 多数条目可追溯；无"这句话哪来的"阻断性疑问 | 若用户不看来源，弱化侧边出处，把校验保留在后台即可 |
| H5 | W8 演示给有招聘经验的人看一次，收集关注点；面试中观察反馈 | W8 + 面试期 | 讲解闭环与取舍能被追问展开，功能堆叠不被当成亮点 | 按反馈补充选型对比文档，不临时堆新功能 |
| H6 | W1 技术 Spike：模型最小请求、服务端出 pptx、规则匹配打分原型 | W1 | 三项各有明确成功/失败记录 | 模型不通换兼容厂商；出图不稳降级为 HTML 预览 + 手动导出；匹配不准先人工选 |
| H7 | W1 按每周可用小时数校准任务量；每周末对照排期偏差 | W1–W8 | 偏差不持续超过一周；超期任务有明确降级记录 | 先砍 P1 子集（实体表简化、第二模型后置），保 P0 闭环完整 |

## 一页速览（打印/评审用）

- **做什么**：个人材料库 + 自有模板卡片 + 可溯源汇报初稿的云端工作台。
- **给谁**：行政/内勤/项目助理等定期写汇报的个人用户；本期不做团队与付费运营。
- **边界**：8 周、单人、复用现有服务器；不做协作、无损套版、自由画布、商业化支付。
- **五目标**：闭环跑通（O1）、可信生成（O2）、模板匹配（O3）、作品集完整（O4）、边界案例（O5）。
- **七个假设**：逐条带验证时点与证伪预案，不靠感觉开发。
