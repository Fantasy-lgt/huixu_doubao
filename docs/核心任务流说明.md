# 核心任务流说明（三条主流程 · 含分支与失败回退）

版本：v1.0 ｜ 阶段：🧪 Design（User Flow / Wireflow）｜ 配套可视化：`核心任务线wireflow.html`（同目录）
定位：前端搭骨架的直接输入。每个节点给出「页面/路由 → 用户操作 → 接口 → 数据 → 分支条件 → 失败回退」。接口为 REST 草案，服务端为权威；无 Key 时本地规则链路必须完整可用（方案 4.3 验收口径 2）。

共用约定（三条流都遵守，不再逐条重复）：
- 所有业务接口经鉴权中间件；401 → 清前端态跳 `/login?redirect=`；资源不归属 → 404，不暴露存在性。
- 写操作成功才更新本地态；失败保留用户已填内容，不产生半成品记录。
- AI 相关失败一律不污染原稿：保留 `drafts.version` / `confirmedVersion`，回退本地规则稿，不自动重试收费调用。
- 外发模型只带本次选中材料子集，外发前弹窗明示份数与标题清单。

## 流一 · 月度汇报生成（P0 主闭环，对应编辑器五步）

**目标**：从空材料状态到下载一份带出处标注、可编辑的月度 PPTX；无 Key 也能走完全程。
**主路径**：登录 → 建稿 → ①选材料 → ②大纲 → ③核对 → ④选模板 → ⑤导出 → 沉淀回库。

| # | 节点 | 页面 / 路由 | 用户操作 | 接口（草案） | 读写数据 | 分支条件 | 失败 / 回退 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| F1-0 | 进入任务 | `/` 工作台；或 `/materials` 预选；或助手抽屉 | 点「新建月度汇报」；或输入指令「做 10 月月度汇报」 | `POST /drafts`（建空草稿） | drafts | 助手路径先做意图识别；表单路径直接进编辑器 | 建草稿失败 → toast 重试，不跳空白页 |
| F1-1 | 意图识别与槽位补齐（仅助手路径） | 助手抽屉 `AssistantDrawer` | 点选月份/类型/场合选项（每题 ≥3 选项） | `POST /assistant/chat`（规则兜底，AI 可选） | slots `{year,month,types,occasion}` | 槽位齐全 → F1-2；缺失 → 一次问清；模型不可用 → 规则关键词兜底 | 模型不可用 → 规则解析；解析不出 → 引导改用表单新建 |
| F1-2 | ① 准备材料 | `/editor/:draftId` 步骤① | 选期间/类型/场合 chips；勾选候选材料 | `GET /materials?period&type&occasion`；`PUT /drafts/:id {rangeFilter, sourceRefs}` | materials、drafts.rangeFilter | 已勾选 ≥1 → 可下一步；0 份 → 主按钮禁用 | 筛选无结果 → 空态 + 「去材料库新建」；材料不足 → 列缺口并建议补哪些月份 |
| F1-3 | ② 大纲确认 | 步骤② | 查看三章节大纲，增删/排序章节，确认 | `POST /drafts/generate`（本地规则优先；`mode=ai` 可选）；`PUT /drafts/:id {sections}` | drafts.sections | 章节非空 → 可下一步；章节为空 → 禁用 | AI 生成失败（见异常矩阵 E1–E4）→ 自动回退本地规则稿，保留用户已圈选材料 |
| F1-4 | ③ 逐页核对 | 步骤③（三栏） | 条目编辑/上下移/删除；点「跳转原文」对照；处理待补充项 | `PUT /drafts/:id {sections[].items}`；`GET /materials/:id` | drafts.sections.items[]、materials | 修改后「已确认」失效需重新确认；warn 项可带提示前进，但导出前处理 | 引用材料被改/删 → 草稿 `confirmedVersion` 清空并标「待重新核对」；来源缺失 → 条目标待补，不静默生成 |
| F1-5 | ④ 模板匹配 | 步骤④ | 看 Top3 打分卡，选「用于本稿」或替换备选 | `POST /templates/match {pageRequirement}`；`PUT /drafts/:id {templateCardId}` | template_cards、drafts | 有适配卡 → 选中；无适配 → 保存元数据卡或选近似卡 | 规则并列时 AI 仅辅助排序；无任何卡 → 用内置默认版式，不阻塞导出 |
| F1-6 | ⑤ 导出 PPTX | 步骤⑤ | 设范围/文件名，过检查清单，点导出 | `POST /exports/pptx {draftId,scope,templateId,fileName}`（W3 接 pptxgenjs，本期占位） | drafts 定稿、template_cards、export_jobs(预留) | 检查项通过/用户确认忽略 → 可导出；存在阻塞项 → 按钮禁用并指明缺什么 | 生成异常 → 保留草稿版本，提示重试或切本地规则；不重复发起收费调用；超长按规则分页或明确拒绝 |
| F1-7 | 沉淀回库 | `/` 工作台；`/materials` | 查看下载文件；草稿出现在草稿列表可续编 | `GET /drafts?kind=drafting` | drafts、materials | 导出成功 → 草稿标记已导出；未导出 → 草稿保留草稿态 | 下载中断 → 草稿仍在，可重新导出，不丢内容 |

**成功判据**：两账号互不可见；无 Key 走通 F1-2→F1-7；有 Key 时 AI 大纲可用且失败不污染原稿；导出文本可编辑、模板配色生效。

## 流二 · 年度汇总导出（P1 子集，确定性聚合为主）

**目标**：基于材料表与实体表确定性聚合出年度覆盖与名单清单，AI 只做措辞连贯化，不自动编造实体。
**主路径**：选年份 → 聚合统计 → 核对覆盖与缺月 → 确认实体候选 → 生成清单 → 导出。

| # | 节点 | 页面 / 路由 | 用户操作 | 接口（草案） | 读写数据 | 分支条件 | 失败 / 回退 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| F2-0 | 进入年度视图 | `/year`；或助手「汇总今年」 | 选择年份（默认当前年） | `GET /year/overview?year=` | materials 聚合 | 有材料 → 出热力；无材料 → 空态 | 接口错误 → 错误态 + 重试按钮，不白屏 |
| F2-1 | 覆盖统计 | `/year` 热力 + 统计卡 | 查看 12 月覆盖格、类型/场合分布 | `GET /year/overview?year=`（确定性聚合，不做业务结论推断） | materials（按 period 聚合） | 覆盖完整 → 正常；缺月 → 斜纹格 + 「缺 X 月」提示 | 缺数据显式标待补，不按内容主观推断补全 |
| F2-2 | 实体候选确认 | `/year` 实体候选区 | 逐条确认/忽略 AI 建议候选（人员/客户/合同） | `GET /entities?year=`；`POST /entities/:id/confirm` | entities、materials.sourceMaterialIds | 人确认才入库；未确认不计入正式清单 | 候选来源材料缺失 → 候选标来源待补，不强行确认 |
| F2-3 | 生成年度清单 | `/year` 「生成年度清单」 | 确认范围（全部实体 / 仅已确认） | `POST /year/compose {year, scope}`（LLM 仅连贯化措辞） | entities + materials | 已确认实体足够 → 生成；为空 → 提示先确认候选或手工录入 | LLM 失败 → 退化为确定性名单 + 时间线纯文本，不阻塞清单产出 |
| F2-4 | 导出年度清单 | `/year` 导出按钮 | 导出清单（带来源引用） | `GET /year/export?year=`（清单文件占位） | entities、materials | 清单含来源引用 → 可导出；来源缺失条目 → 单独标注 | 导出失败 → 保留页面数据，重试；不重复请求 LLM |
| F2-5 | 沉淀复用 | 回链到材料/草稿 | 点来源跳回对应材料或月度草稿 | `GET /materials/:id` | materials、drafts | 跨月同一事项不重复计为新增成果 | — |

**成功判据**：月份覆盖与缺月由材料记录决定；实体「先建议、人确认、后落库」；每条清单带来源材料引用；不输出绩效结论类主观判断。

## 流三 · 模型 Key 配置（设置页，AI 能力前置开关）

**目标**：让用户安全配置 1 家兼容协议模型并验证连通；无 Key 时不阻塞本地规则主流程。
**主路径**：进入设置 → 选 Provider → 粘贴 Key → 连通测试 → 保存加密 → 模式切换生效 →（可移除回退本地）。

| # | 节点 | 页面 / 路由 | 用户操作 | 接口（草案） | 读写数据 | 分支条件 | 失败 / 回退 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| F3-0 | 进入配置 | `/settings` 模型 Key 区块；或编辑器步骤②提示「当前本地规则模式」 | 打开设置页 | `GET /model-keys` | model_keys | 已有有效 Key → 显示掩码状态 + 移除按钮；无 Key → 显示配置引导 | — |
| F3-1 | 选择 Provider | 设置页表单 | 选首期 Provider（DeepSeek 兼容协议；其余预留灰显） | — | — | 仅开放 1 家，避免多模型路由复杂度 | 未选 Provider → 测试按钮禁用 |
| F3-2 | 粘贴 Key | 设置页输入框 | 粘贴 Key；前端仅掩码显示，不回显明文 | — | — | 非空才可测试；格式明显异常给即时提示 | 前端不缓存明文；离开页面不残留输入值 |
| F3-3 | 连通测试 | 点「测试连通」 | 发起最小非流式请求 | `POST /model-keys/test {provider, key}`（服务端代发，Key 不经前端日志） | model_keys（测试不落库或临时态） | 成功 → 绿「连通通过」；失败 → 按错误码分类提示（见下） | 见异常矩阵 E1–E4；测试失败不写入正式 Key |
| F3-4 | 保存生效 | 点「保存」 | 保存加密 Key | `POST /model-keys {provider, encryptedKey, label}` | model_keys（服务端加密存储） | 保存成功 → 编辑器/助手标识「AI 可用」；失败 → 提示重试，保留输入 | Key 不进备份导出、不进日志；备份文件剔除该字段 |
| F3-5 | AI 外发确认 | 编辑器步骤②/助手生成前 | 查看本次外发材料份数与标题清单，确认后才调用模型 | 复用 `POST /drafts/generate {mode:ai}` | drafts、materials 子集 | 用户确认 → 发起；取消 → 不发起、不扣费 | 外发范围始终是本次子集，不是全库 |
| F3-6 | 移除 / 回退 | 设置页「移除 Key」 | 二次确认后删除 | `DELETE /model-keys/:id` | model_keys | 移除成功 → 立即切回本地规则模式；历史草稿与已生成内容保留 | 移除不删除任何材料/草稿；模式切换即时生效 |

**连通测试结果分类（F3-3，前端提示与回退）**

| 错误码 / 现象 | 前端表现 | 处理 / 回退 |
| --- | --- | --- |
| 200 且返回结构合法 | 绿点「连通通过」，可保存 | 进入 F3-4 |
| 401 / 403 鉴权失败 | 红「Key 无效或无权限，请检查后重试」 | 不保存；引导重新粘贴 |
| 429 限流 | 黄「当前限流，请稍后再试」 | 不反复重试；稍后手动再测 |
| 超时 / 网络不可达 | 黄「连接超时，检查网络或服务器出网策略」 | 保持本地规则模式 |
| 返回坏 JSON / 结构不符 | 红「返回格式不符兼容协议」 | 记录原始错误码（不回显 Key），切换 Provider 预留位 |
| 服务端 5xx | 黄「服务暂时不可用」 | 稍后重试；主流程仍可走本地规则 |

**成功判据**：Key 服务端加密、前端只见掩码；测试失败不入库；移除后本地规则链路照常；无 Key 不影响 F1 主闭环。

## 异常处理矩阵（跨三条流共用）

| 场景 | 触发节点 | 前端表现 | 系统回退 / 保护动作 |
| --- | --- | --- | --- |
| 未登录 / 会话过期 401 | 任意业务接口 | toast「登录已过期」→ 跳 `/login?redirect=` | 不写半成品；清前端态 |
| 越权访问他人资源 | 任意 GET/PUT/DELETE :id | 404「不存在或无权访问」 | 服务端记安全日志，不暴露资源存在性 |
| 材料重复 409 `MATERIAL_DUPLICATE` | F1-2 前置入库 / 材料库新建 | 提示「与已有材料重复」 | 不写入；保留表单 |
| AI 鉴权失败 401/403 | F1-3、F3-3 | 红提示；大纲区回退本地稿 | 不污染原稿；不自动重试收费调用 |
| AI 限流 429 / 超时 | F1-3、F2-3、F3-3 | 黄提示 + 本地规则结果兜底 | 降级为本地规则/确定性聚合 |
| AI 坏 JSON / 越界引用 | F1-3 输出校验 | 整份拒绝，保留原稿 | 沿用初代 sourceIds + evidence 逐字引用校验 |
| 导出生成失败 | F1-6、F2-4 | 提示失败原因，草稿版本保留 | 可重试；不重复发起模型调用 |
| 引用材料被更新/删除 | F1-4 | 草稿标「待重新核对」 | `confirmedVersion` 清空，版本号联动 |
| 无 Key | 全链路 | 标识「本地规则模式」 | 规则整理链路完整可用，不阻塞导出 |

## 前端骨架对接清单（按此建组件与状态）

1. **路由**：见 `IA站点地图-路由与数据对照表.md`；本文件三条流的「页面/路由」列与之逐一对齐。
2. **状态机**：编辑器 `step:1..5`（F1-2→F1-6）；年度视图 `year`、`candidates[]`；设置页 `keyStatus: none|testing|ok|error`。
3. **接口调用顺序**：每条流按表中 # 顺序发请求；前一节点未成功不进入下一节点主按钮。
4. **空/错态组件**：三条流均需 empty（无材料/无候选/无 Key）、loading（生成/测试/导出）、error（可重试）三态占位。
5. **白名单动作**：助手抽屉只允许「查询、生成草稿、推荐模板」；删除、导出、外发确认不在助手内直接执行。
