## 🕹 Project Info

### 📝 Project Brief

在初代本机版「汇序 v0.1」（材料归档→本地规则整理三章节初稿→来源核对→导出可编辑 pptx，已跑通并通过自动测试）基础上，演进为**云端账号版个人通用 AI 汇报助手**：职场人沉淀个人材料库，通过表单或一句话指令触发整理，AI 按自有模板卡片生成带出处可核对的汇报 PPT，支持年度多维汇总。双重目标：①验证"材料沉淀+模板复用+溯源整理"是否真能减少汇报耗时；②产出一份可讲解、可演示、可部署的求职作品集。

**约束**：单人开发；复用已有服务器；预算敏感；技术栈贴合既有经验（Vue3 / Node / PostgreSQL / pptxgenjs / SSE）；不做团队协作、不承诺任意母版无损套版、不做自由画布、会员支付后置。

**Key dates**
- Kick-off：2026-10-31
- 里程碑 M1（W3 末 2026-11-22）：账号隔离 + 本地整理闭环可演示
- 里程碑 M2（W5 末 2026-12-06）：AI 受控生成 + 对话助手简化版
- 里程碑 M3（W6 末 2026-12-13）：模板卡片库 + 三栏编辑器
- 目标交付：2026-12-27（W8 末，部署上线 + 作品集包装）

### ✅ The Objectives（SMART，区分两层目标）

产品目标（验证型，不预设收益数字）：
1. **任务闭环**：注册用户能在一次会话内完成"导入材料 → 生成初稿 → 核对 → 导出 pptx"，核心任务无阻断性错误（W3 末验收）。
2. **可信生成**：AI 生成条目 100% 带可回溯来源或显式"待补充"标记；模型失败不污染原稿（W5 末验收）。
3. **模板复用**：大纲页可自动匹配模板卡 Top3，切换可见预览，导出套用版式（W6 末验收）。

作品集目标（求职导向）：
4. 8 周内产出可部署演示版本 + 架构文档 + 2 分钟演示脚本，能现场讲清选型理由、失败处理与数据隔离设计。
5. 沉淀 3 类可讲的失败/边界案例（鉴权失败、材料不足、无适配模板），体现产品判断而非功能堆砌。

### 👤 The Stakeholders

- 发起人 / 唯一决策者：本人（产品 + 设计 + 开发一体）
- 潜在首批试用者：制造业综合部受访者 1 位（已有访谈片段）；待再找 1–2 位行政/内勤朋友
- 未来用户（假设）：中小企业行政/人力/项目助理；本期不接触付费客户

### 🧑‍🚀 The Team

- AI 辅助：方案整理、代码草稿、文档生成；最终判断与验收由本人负责

## 接下去怎么做（按执行顺序）

### 第一优先级：本周（W1，11/02–11/08）先补设计缺口，再进开发

1. **半天**：收口 Brief 一页纸 + SMART 目标（直接用本文 Project Info 扩写）。
2. **半天**：假设画布（4 条假设 + 验证方式 + 证伪处理）。
3. **1–2 天**：IA 站点地图 + 三条核心任务 wireflow + 8 个核心页面低保真线框（线框决定 W2 前端怎么搭，是当前最该先出的设计物）。
4. **1 天**：技术 Spike 三件套（模型连通、pptx 云端生成、母版填充可行性探针），先排雷再写业务代码。
5. **并行**：数据表定稿 + 账号/材料库 PRD（字段规则、页面、验收用例），作为 W2 开发输入。
6. **半天**：指标字典初稿 + 4 份 ADR 备选对比（面试素材，顺带完成 Ideate 收口）。

### 第二优先级：开发期穿插（W2–W6）

- 每个模块开发前补该模块页面规格与状态清单；开发中补自动测试。
- W3、W6 各安排一轮轻量可用性走查，问题清单排序修复，不追求一次完美。
- 访谈记录在 W2 内补完（约受访者 30 分钟语音转文字即可）。

### 第三优先级：收尾（W7–W8）

- 部署手册、发布清单、回滚预案；演示脚本录屏；复盘文档；指标口径落地到服务端日志。

### 明确不做的方法（单人作品阶段裁剪，避免形式负担）

- Focus Group、问卷大样本调研、Shadowing 田野观察：用户量不足，用 1–2 人深访替代。
- A/B 测试、Cohort 留存分析、NPS 系统：无流量基础，先记录定性反馈。
- 完整 Design System、高保真 UI、无障碍专项：统一基础组件与配色即可，视觉美化后置。
- 多版本高保真原型：低保真线框 + 可点击骨架足够验证。
