# 交付前自测清单（静态 + 实现核对 + 声明）

本清单是 HS2/HS7 与"问题列表第 1 条"的落地。**静态部分**由 `scripts/selfcheck.py` 自动查；**实现核对部分**记录结构、状态、处理器和适配规则。任何一项不合格：先修复，或在交付说明显式标"待补充"，**不得沉默交付**。

## A. 静态门（通过 python3 跑 selfcheck.py，必须先过）

```bash
python3 scripts/selfcheck.py <交付目录> --json=selfcheck.json
```
- FAIL=0 才放行；FAIL>0 必须整改（死链、缺 viewport、外部 CDN 资源、缺 design.md 等）。
- WARN 逐条看：能修则修，其余转入 B 部分核对实现。

## B. 实现核对

逐项检查元素、处理器、状态源、反馈文案和适配规则；发现死链、死按钮或静态占位即不合格。

1. **导航 / 按钮 / 锚点**：每一个 `<a>`、`<button>`、Tab、锚点都有目标和处理器。**死链、死按钮 = 不合格**。
2. **表单**：必填校验、合法值提交、成功和失败反馈均有对应规则与文案。无反馈定义 = 不合格。
3. **切换类组件**（轮播 / Tab / 折叠 / 下拉 / 步骤条）：具备状态源和内容更新逻辑，不用静态占位冒充切换。
4. **移动端 375px**：有导航收起方案、溢出处理和达标的主操作触控尺寸。
5. **多断点**：375 / 768 / 1024 三档均有明确的阅读顺序、换行和图文关系规则（对应 RESP-02）。
6. **离线资源**：承诺离线包时，图片、样式、脚本和字体均使用包内相对路径（对应 HS3）。
7. **异常/边界态**：空数据、超长文案、加载中、加载失败、无权限——需求涉及的都要有可见的界面表现（对应 content-and-states.md）。

## C. 声明核对（发出前最后一步）

- 打开草拟的交付说明，把每一条"已完成 / 已适配 / 全部使用 Token / 包含 X"拎出来。
- 逐条回到产物指认证据（页面、文件、代码、实现记录）。
- 指不到 → **删掉该声明，或补齐产物**。见 `claim-consistency.md`。

## 判定

- 全绿，或未过项已全部显式降级标注为"待补充/例外" → 可交付，并给出交付回执。
- 存在未标注的 FAIL 或 B 部分缺失项 → **半成品，禁止声明完成**。
