# 内容落地、场景全状态、B 端语义与渐进式声明（HS6 / HS7）

问题列表第 7、8、9 与"渐进式"落地。核心：**别停在指标清单和概念稿，把功能落到具体页面，把有状态的场景给全。**

## 1. 内容落到具体页面（item 7）

设计规范不能只是一张"指标/组件清单"。每个**核心功能**都要展开成**可看的具体页面/区块**：

- 例：适老健康 App —— 不能只写"支持紧急呼叫"，要落成 **SOS 一键呼救页**（大按钮、确认弹层、呼叫中状态）、**语音播报**（可见开关+朗读态）、**家人互动**（家庭成员卡、消息/提醒流）。
- 判定：需求里点名的每个功能，都能在产物里指到承载它的页面或组件。指不到 = HS6 不过。

## 2. 使用场景给全状态（item 8）

有状态的场景**不能只给一个态**：

| 场景类型 | 必须给的状态（示例） |
|---|---|
| 音乐 App | 主播放态 + 歌词展开态 + 暂停态 + 列表态 |
| 播放/进度类 | 空/加载中/播放中/完成/失败 |
| 游戏/数据看板 | 要有"产出在跑"的**动态感**（动效/滚动数字/实时更新），不能全是静态数字 |
| 表单/流程 | 初始 + 填写中 + 校验错误 + 提交中 + 成功 |
| 列表/内容 | 有数据 + 空态 + 加载 + 加载失败 + 超长内容 |

判定：场景的关键状态是否都有可见实现（对应实现核对第 3、7 项）。

## 3. B 端工程化落地（item 9）

- **业务语义映射**：视觉符号 → 业务含义（红=风险/黄=待处理/绿=正常），在 design.md 写清。
- **密度切换**：紧凑/标准/舒适三档参数。
- **关键参数齐全**：色值、字体名、断点、栅格都给具体值，不停留在概念。

## 4. 渐进式开发的显式声明（progressive，HS7）

- 妙搭里**未完成的页面/功能必须显式标注"待补充"**（页面上可见 + 交付说明列明），**禁止把半成品声明为已完成**。
- 用占位数据/占位图时，显著标注"演示占位，非真实数据/资源"。
- `selfcheck.py` PROG-01 会检出 `待补充/TODO/lorem/占位/undefined` 等标记，提醒你要么完成、要么显式声明。
- 产品侧建议：尽量丰富妙搭附件（真实图片、mock 文件），减少裂图与空白页。

## 判定汇总

- 每个点名功能有页面、每个有状态场景有全状态、B 端有语义+密度、未完成项已显式标注 → HS6/HS7 通过。
- 出现"只有指标清单没有页面""只给一个态""半成品当成品" → 不合格，回去补或显式降级。
