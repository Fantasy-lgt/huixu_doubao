# 声明与实物一致性核对（HS1）

问题列表第 4 条落地：**交付前把每一条声明与实物逐条核对，对不上就删声明或补产物。**
这是整个交付门里最容易被忽视、也最伤信任的一环——措辞上的"已完成"骗不过用户真实点开产物的那一下。

## 核对流程

1. **抽取声明**：把你打算写进交付说明/回复的每一句"结论性话术"拎成清单。高危词：
   - "已完成 / 已实现 / 已适配（移动端/375px/暗色）"
   - "包含 X 页 / X 功能 / X 组件"
   - "全部使用 Design Token / 全部无障碍达标"
   - "响应式 / 可交互 / 支持 Y"
2. **逐条找证据**：每条声明回到产物里指认——具体哪个文件、哪个页面、哪段代码、哪项实现记录。
3. **三选一处理**：
   - 指得到证据 → 保留声明；
   - 指不到但值得做 → **补齐产物**再声明；
   - 指不到且本轮不做 → **删除声明**，或改写为"待补充：<原因>"。

## 对照表模板（随交付附上）

| 声明 | 证据（页面/文件/实现） | 结论 |
|---|---|---|
| 已适配移动端 375px | pages/*.html + 375px 断点与布局规则 | ✅ 保留 |
| 全部使用 Design Token | design.md token 表 + CSS 变量引用 | ✅ 保留 |
| 包含家人互动页 | （产物中无此页） | ✂️ 删声明 / 标"待补充" |
| 无障碍全部达标 | 仅正文达标，2 处大字未测 | 改写为"正文达标，2 处待测" |

## 常见对不上的坑

- "响应式"只在文字里说，没有 `@media` 或布局规则 → 删或补（对应 RESP-01/02）。
- "可交互"但按钮没有处理器 → 实现核对会暴露（DL-02）。
- "全部 Token"但存在硬编码色值 → 抽查 CSS 是否有游离 `#hex`。
- "已适配暗色"但没有 dark token/媒体查询 → 删或补。

## 判定

交付说明里**每一条声明都能在对照表指到证据**，无无证据声明 → HS1 通过。存在"说了但产物里没有"的声明且未降级 → 不合格。
