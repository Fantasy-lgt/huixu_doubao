# 生产级交付标准 —— 交付门，不是又一套设计方法

**这是所有"可运行网页 / 原型 / 设计系统"产物离开你手之前的最后一道门。** 设计怎么做由其他 Skill 决定；这里只回答一个问题：**这份产物是不是"能直接用的成品"，而不是"看起来完成的半成品"。**

一句话红线：**没有过这道门，就不能对用户说"已完成"。** 声明必须由产物证据支撑，不能由措辞支撑。

## 何时用 / 何时不用

| 用 | 不用 |
|---|---|
| 交付妙搭网页应用(app_builder html) / 可运行原型前 | 纯视觉海报、企划案(→ doubao-visual-creative) |
| 交付设计系统 / Design Token 规范前 | 纯数据图表(→ chart-generator) |
| 用户要"生产级""能落地""可交付"的 UI | 后端逻辑、纯格式转换 |
| 界面质量审查、验收既有实现 | 与界面无关的问答 |

## 七条生产级硬标准（门禁）

每条给出**判定口径**与**证据要求**。凡不满足：先修复，或在交付说明中显式降级标注，二者必居其一，**不得沉默交付**。

| # | 硬标准 | 判定口径 | 证据 |
|---|---|---|---|
| **HS1 声明=实物** | 交付前把"已完成 / 包含 X / 全部使用 Token / 已适配 Y"逐条与真实产物核对，对不上就删声明或补产物 | 每条声明能在产物里指到具体页面/文件/代码 | 声明↔产物对照表 |
| **HS2 实现完整性** | 响应式、交互、异常状态**必须有可检查的 HTML/CSS/JS 实现**，不能只靠文字描述 | 有真实 HTML + 实现清单 | selfcheck + 声明对照 |
| **HS3 离线资源完整** | zip 导出含图片与全部资源；图片不走平台 CDN 绝对路径（本地化或降级）；依赖宿主协议的功能标注"离线不可用" | 资源均为包内相对路径 | `selfcheck.py` OFF-01/02/03 通过 |
| **HS4 无障碍达标** | 对比度、字号、px/pt 不混用、交互有反馈、规范文档自身可读 | 达 WCAG 2.2 AA 阈值 | `accessibility-wcag.md` 逐项 |
| **HS5 规范硬交付** | 必须实际交付 `design.md`(色值/字体/间距/断点参数)，不能只给预览链接或静态图 | 文件存在且四类参数齐全 | `selfcheck.py` SPEC-01/02 + `design-spec-template.md` |
| **HS6 内容落地+场景完整** | 规范不停留在指标清单，核心功能展开到具体页面;有状态的场景给全状态(不是单态);B 端补业务语义与密度切换 | 每个点名功能有对应页面/状态 | `content-and-states.md` |
| **HS7 渐进式显式声明** | 未完成的页面/功能必须显式标注"待补充",禁止把半成品声明为已完成 | 无"隐藏的未完成" | selfcheck PROG-01 + 交付说明 |

> 门的立场：HS1/HS2/HS3/HS5 是**可由静态证据判定的阻断门**（不达标=不合格）；HS4/HS6/HS7 含需人工判断的部分，脚本能查的查、查不了的进入实现清单。**脚本查不到 ≠ 通过**。

## 附件交付 Gate（按需）

在线预览页可作为网页、原型和设计规范类交付的有效验收入口。仅当用户明确要求离线包、源文件、可开发接管或断网运行时，才必须提供以下可下载附件：

- `delivery.zip`：包含 `index.html`、本地 CSS/JS/图片/字体（如有）、`design.md` 与 `README.md`；资源均使用包内相对路径。
- `design.md`：色值、字体、间距、圆角、断点、组件状态、交互规则与已知限制齐全。
- `README.md`：打开方式、主要交互清单、演示数据替换点、验证记录与限制说明。

**禁止**在未实际提供附件时，把网页内一段“设计说明”、回复中的文字、或只有文件名的页脚当作 `design.md`/离线包已交付。附件链接必须在最终回复、网页“交付物”区和交付回执中三处一致出现，并记录文件名与声明的一致性。

若当前平台无法上传附件，明确写“仅在线预览，未交付离线包”；这不影响在线网页或原型本身的验收，但不得声称“可离线使用”或“可直接交付开发”。网页内可读的设计说明可以作为在线设计规范交付。

## 实现证据 Gate（必须）

最终回复前，逐项记录导航、核心主操作、每类状态切换、表单成功/失败反馈、375px 响应式与至少一个键盘焦点路径的实现位置和目标状态。

仅有功能声明而找不到对应结构、样式、事件处理或状态定义的内容，不能计入已交付功能清单。

### 实现证据最小表（P1）

交互型原型、官网、H5、播放页、设计规范页交付前必须填写以下表。任何可见入口没有目标状态或实现位置时，删除该入口、改为非交互展示，或继续实现后交付。

| 控件/入口 | 事件 | 目标状态 | 实现位置 | 结论 |
|---|---|---|---|---|
| 导航/锚点/底部 Tab | click/tap | 路由、锚点或业务内容变化 | 元素、处理器或路由定义 | 完整/缺失 |
| 订阅/表单/搜索 | submit/input | 校验、结果列表或错误提示变化 | 校验规则与状态定义 | 完整/缺失 |
| 轮播/展开/模式切换 | click/tap | 正文、图片或状态真实变化 | 状态源与更新逻辑 | 完整/缺失 |
| 主业务操作 | click/tap | 播放、点赞、收藏、修炼、打坐等状态变化 | 状态值、计数或面板定义 | 完整/缺失 |

### Design Token 与可移植性回归（P1）

- 设计规范声明的字号、单位、间距、触控目标、颜色 Token 和组件状态，必须与最终页面 `computed style` 或规范文件一致；不得混用 px/pt 后仍声称符合移动端标准。
- 跨页面共享同一状态清单；首页、详情页、用药页、播放页等显示的数量、选中项和进度必须来自同一源，不能各自写死。
- 承诺可下载、离线运行或开发接管时，外部图片、字体、CSS、JS 和平台 CDN 必须进入包内相对路径。

## 交付前三步自测流程

```
第 1 步  静态体检   →  python3 scripts/selfcheck.py <产物目录或HTML> [--strict]
第 2 步  实现核对   →  按「实现核对清单」记录交互、375px、状态和资源对应位置
第 3 步  声明核对   →  按「声明↔产物对照表」逐条勾对，删不实声明 / 补缺口 / 标待补充
```

三步全绿或全部显式降级，才能交付。任何一步有未解决 FAIL 且未标注，判为**半成品，不得交付**。

### 第 1 步：`scripts/selfcheck.py`（静态检查门）

`selfcheck.py` 不设置可执行权限，统一通过 `python3` 调用。

```bash
python3 scripts/selfcheck.py path/to/delivery_dir        # 扫描整个交付目录(推荐)
python3 scripts/selfcheck.py path/to/index.html          # 扫描单文件
python3 scripts/selfcheck.py path/to/dir --strict        # WARN 也视为不通过
python3 scripts/selfcheck.py path/to/dir --json=out.json # 结构化结果留档
```

退出码 `0`=无 FAIL 放行；`1`=有 FAIL(或 --strict 下有 WARN)必须整改。检查项与硬标准映射：

| 检查 ID | 对应 | 严重度 | 含义 |
|---|---|---|---|
| DL-01 | HS2/item1 | FAIL | 空/占位锚点 `href="#"`/`""` 且无处理器 = 死链 |
| DL-02 | HS2/item1 | WARN | 按钮无静态可见处理器，需核对事件实现 |
| RESP-01 | HS2 | FAIL | 缺 `<meta viewport>`，375px 声明不成立 |
| RESP-02 | HS2 | WARN | 无 `@media` 断点，需核对多尺寸适配实现 |
| NAV-01 | item1 | WARN | 有 `<nav>` 无汉堡/菜单切换控件 |
| FORM-01/02 | item1 | WARN | required 输入无校验反馈 / form 无提交控件 |
| OFF-01/02/03 | HS3 | FAIL/WARN | 外部 CDN 绝对资源 / CSS 外链 / 目录无本地图片 |
| A11Y-01/02/03 | HS4 | WARN | 缺 lang / img 缺 alt / px 与 pt 混用 |
| SPEC-01/02 | HS5 | FAIL/WARN | 缺 design.md / design.md 参数不全 |
| PROG-01 | HS7 | INFO | 检出占位符，未完成项须显式标注 |

### 第 2 步：实现核对清单（脚本覆盖不到）

见 `references/selfcheck-checklist.md`。核心：逐项核对导航/按钮/锚点的目标与处理器；**表单**具备必填校验与提交反馈定义；**轮播/切换/Tab** 具备内容变化逻辑而非静态占位；**移动端** 375px 下汉堡菜单、横向滚动和溢出有明确适配规则；**离线包**的图片与资源使用包内相对路径。

### 第 3 步：声明↔产物对照（HS1）

见 `references/claim-consistency.md`。规则：先列出你打算写进交付说明的每一条声明 → 逐条在产物里指认证据 → 指不到的，**删声明或补产物**，绝不保留无证据的"已完成"。

## 交付回执格式（必须随产物给出）

```
交付回执
- 产物：<相对路径/预览链接>；zip：<含资源，可离线打开 是/否>
- 自测：selfcheck FAIL=<n> WARN=<n>（结果 out.json 附）
- 实现核对：导航/按钮 <完整项/总数>；表单 <完整/缺失>；切换类 <完整/缺失>；375px <完整/缺失>；离线资源 <完整/缺失>
- 设计规范：design.md <已交付，含 色/字/间距/断点>
- 无障碍：对比度正文≥4.5:1 大字/图形≥3:1 <达标/例外清单>
- 待补充（显式）：<页面/功能 + 原因>，无则写"无"
- 事实边界：<演示占位数据、依赖宿主协议不可离线见 的部分>
```

无法给出某项证据时写明"待补充/不适用"，不得留空默认通过。
