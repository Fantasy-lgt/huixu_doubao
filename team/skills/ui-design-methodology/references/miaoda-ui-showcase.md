# 妙搭网页上的 UI 效果展示方法论

> 本专家默认交付载体是**妙搭网页**（`构建网页应用` arch_type=html）。本文件规定"如何在妙搭网页上把 UI 设计效果展示到位"，让评审一眼看到设计价值、且效果有实现依据。`AGENTS.md` 引用本文件。交付前必须过 `skills/ui-delivery-standard` 的自测门；美感规则见 `design-methodology.md`。

## 核心原则

- UI 设计的最终形态是**可预览、可操作的真实界面**，不是静态截图或文字描述。
- **图表和数据可视化是界面的一部分**：用设计系统的色板/字体/间距内联实现，跟随页面响应式与暗色一起工作，不外链、不割裂到别处。

## 1. 多状态同页展示

- 关键组件平铺出状态矩阵：default / hover / active / focus / disabled / error / loading / empty。
- 页面级展示空状态、加载态、错误态与**极端数据**（超长文本、大数字、无数据）下的表现。

## 2. 真实交互、可操作

- 导航、按钮、锚点、表单、切换、轮播必须**真实可点、有真实反馈**，不做假按钮、死链接。
- 交互后状态变化可见：选中、展开、切换、表单校验提示都要真的发生。

## 3. 响应式适配

- 至少覆盖 **375（移动）/ 768（平板）/ 1280（桌面）** 三档；375px 必须有适配设计与实现依据。
- 移动端导航给出**可用的**汉堡菜单/抽屉真实交互，而不仅是一个图标。

## 4. 主题与暗色

- 设计含暗色或多主题时，页面提供切换并**全量覆盖**，不留漏改的组件或写死的颜色。

## 5. 设计系统可见（成品 + 背后的体系）

- 页面内置一个"设计规范区"：色板（含色值）、字体阶梯、间距、圆角、阴影、组件用法，与 `design.md` 完全一致。
- 让评审既看到成品页面，也看到背后的 token 体系——这是 UI 设计师区别于"随手做个页面"的关键。

## 6. 情境化展示（增强代入感）

- 可用设备框（手机/浏览器 chrome）承载界面，强化"这是真实产品"的观感。
- 关键流程用多屏串联展示（引导 → 主流程 → 结果），体现设计的连贯性。

## 7. 微交互与动效

- 关键反馈加入克制的微交互（按钮按压、卡片 hover、加载骨架屏）；时长与缓动见 `design-methodology.md` 第 9 节。
- 尊重 `prefers-reduced-motion`。

## 8. 评审视角自检

- 首屏是否能快速传达核心界面与设计亮点？
- 每一个"已完成 / 已适配 / 全部用 token"的声明，页面上是否都有真实证据？（统一交给 `ui-delivery-standard` 自测门核对）

## 图表在妙搭网页里怎么呈现（连贯口径）

1. **默认**：在页面内用 HTML / CSS / SVG **内联实现**，颜色取自设计 token，坐标轴/图例/标签清晰，图形对象对比 ≥ 3:1，随页面响应式与暗色一起工作。
2. 数据必须真实；若使用示例数据，必须在页面 `## 数据来源与采用建议` 中标为"仅占位·勿据此决策"，并说明仅用于版式/交互/视觉占位。
3. **离线可用**：不引用外部 CDN/字体，可随 zip 导出。
4. **唯一例外**：当交付物本身是**飞书云文档**时，图示才改走 `chart-generator` 指向的 `beautiful-feishu-whiteboard` 画板路径——网页交付不涉及画板，二者不混用。
