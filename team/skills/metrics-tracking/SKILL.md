# 产品指标与看板

## 目标

让团队知道产品是否持续创造用户价值、为什么变化、谁应采取什么动作。指标体系不是指标大全，看板也不是填满示例数据的展示页。

## 1. 先锁定决定和阶段

开始前明确：

- 产品形态、目标用户和核心任务；
- 当前处于探索期、成长期还是成熟期；
- 本次指标要支持上线、迭代、资源分配、增长还是经营判断；
- 已有数据源、事件、基线和历史口径；
- 谁看、多久看一次、看到异常后能做什么。

缺少产品形态时给条件式候选，不直接指定唯一北极星。缺少真实基线时先定义口径、埋点和基线建立步骤，不编造当前值或目标值。

## 2. 画最小价值因果链

用一条短链连接：

`产品动作 -> 用户行为 -> 用户任务成功 -> 可持续用户价值 -> 业务结果`

区分四类指标：

- **北极星**：代表核心价值被稳定交付；
- **驱动指标**：解释价值由哪些行为和环节产生；
- **诊断指标**：定位漏斗、分群、质量或性能问题；
- **护栏指标**：防止以质量、安全、公平、成本或长期价值换短期增长。

过程量不能自动成为北极星。登录、点击、对话、生成、token 和使用次数上升，可能只是重复尝试、质量下降或路径变长。

## 3. 北极星五问门

对每个候选北极星逐项回答：

1. 它具体代表用户完成了什么有价值的任务？
2. 它是否领先于留存、续费或长期使用，而不只是结果滞后？
3. 团队能否通过无价值动作刷高它？
4. 是否存在“数值改善，但真实用户结果变差”的反例？
5. 需要什么质量、成本、安全或长期价值护栏？

任一反例未被定义或护栏处理时，候选指标不能成为北极星。

AI 产品优先使用“达到质量门的成功任务/工作流/价值会话”，而不是总对话量。有效价值必须由可观察条件定义，例如任务终点达成、结果被采用、无关键错误、限定窗口内无同意图返工；条件需按产品场景校准。

低频功能不能直接套高频活跃指标。优先考虑：

- 目标场景渗透率；
- 周/月成功完成该任务的用户或团队数；
- 符合使用机会的人群中完成价值任务的比例。

“符合使用机会”的分母必须可识别；无法识别时先用不依赖争议分母的计数指标建立基线。

## 4. 按阶段取舍

| 阶段 | 核心问题 | 主指标侧重 |
|---|---|---|
| 探索期 | 目标用户是否能稳定获得核心价值 | 任务成功、价值采用、质量门、复用信号 |
| 成长期 | 价值能否稳定扩散并形成留存 | 留存、团队扩散、场景渗透、单位成本 |
| 成熟期 | 价值能否健康转化为经营结果 | 收入、续费、效率、规模、安全与利润质量 |

同一阶段只突出一个主北极星。不要把所有指标一视同仁；明确本周期唯一主攻方向，以及暂不优化的指标。

## 5. 指标定义卡

每个关键指标至少包含：

| 字段 | 要求 |
|---|---|
| 名称与用途 | 支持哪个决定，异常时影响什么动作 |
| 公式 | 分子、分母和聚合方式 |
| 人群与排除 | 目标角色、资格、机器人/测试/重复事件处理 |
| 时间窗 | 日、周、月、滚动或 cohort |
| 数据源 | 事件、业务表、模型评测或人工抽检 |
| 基线与目标 | 当前状态；目标依据与重校准条件 |
| 刷新与 owner | 更新频率、解释和处置责任 |
| 已知偏差 | 延迟、漏报、幸存者偏差、低频或跨端问题 |

没有基线、样本、流量和数据质量时，目标保持为“待定参数”。先完成基线期，再由业务、产品和数据共同定门槛。

## 6. AI 产品质量层

按任务选择必要维度，不机械全选：

- 任务成功率与结果采用率；
- 一次完成率、重复追问率、返工率和人工接管率；
- 事实错误、幻觉、拒答、误拒和高风险错误；
- 意图识别、检索命中、引用覆盖和证据可追溯；
- 延迟、可用性、吞吐和单位成功任务成本；
- 安全拦截、申诉、审计和隐私事件。

平均质量不能掩盖高代价错误。直接面向客户、投标、医疗、资金或安全场景时，单列严重错误率和人工接管门，并作为发布护栏。

## 7. 最小埋点集

从核心任务而非按钮列表推导事件。最小集合通常包括：

1. 进入目标场景；
2. 开始核心任务；
3. 成功完成任务；
4. 失败及错误类型；
5. 重试、返工或人工接管；
6. 结果采用、导出或进入下游；
7. 负反馈、安全拦截或申诉。

每个事件写触发时机、主体、对象、前后状态、结果、错误码、去重键、关键属性、版本和隐私边界。跨端身份、延迟到达、补发、取消和回滚需要明确处理。

## 8. 看板架构

看板必须同时回答“看什么、怎么看、异常后做什么”。

用户明确要求“看板”或“仪表盘”时，文本框架不是最终交付。必须同时交付：

1. 可编辑指标字典与口径说明；
2. 可实际打开和预览的看板原型，优先使用运行时的 `构建网页应用`；不可用时使用飞书文档 HTML5 block；
3. 角色或阶段切换、时间或分群筛选、指标下钻入口、告警与行动区；
4. 空态、加载态、错误态和“暂无基线/目标”的真实展示，不用虚构健康数字填满页面。

看板原型至少验证一次默认视图与一次筛选/切换后的状态变化，并检查窄屏无溢出。仅有表格、布局文字、画板、静态截图或源码文件时，状态只能写“看板方案已设计，交互看板未完成”，不得宣称看板已交付。

| 受众 | 默认关注 |
|---|---|
| 管理层 | 北极星、趋势、基线/目标状态、主要风险与需拍板事项 |
| 产品/运营 | 驱动漏斗、分群、场景采用、留存和实验 |
| AI/质量 | 任务成功、采用、返工、错误、人工接管和评测 |
| 工程/SRE | 延迟、错误、可用性、吞吐和单位成本 |
| 安全合规 | 高风险命中、拦截、申诉、审计和数据处理 |

布局顺序：北极星与状态 -> 驱动树 -> 关键漏斗/分群 -> 质量与护栏 -> 实验和行动。不同角色可有不同视图，但共用同一指标字典和时间口径。

每个告警绑定：

- 触发条件及依据；
- 严重级别；
- 责任角色；
- 排查路径；
- 立即动作、升级和恢复条件。

阈值未知时先采集基线，不用红黄绿制造已知健康状态。

## 9. 落地顺序

1. 对齐产品阶段、核心任务和唯一北极星候选；
2. 通过五问门，确定驱动指标和护栏；
3. 完成指标定义卡与数据可得性审计；
4. 上线最小事件集并检查去重、漏报和延迟；
5. 跑完基线期，再制定目标与告警；
6. 搭建管理层、产品和质量视图；
7. 建立固定复盘节奏，每次只形成少量明确行动；
8. 指标定义、事件版本或产品阶段变化时更新字典和口径。

## 10. 复盘输出

每次复盘按“事实 -> 解释 -> 决定”收口：

- 事实：变化、口径、时间、分群和数据质量；
- 解释：主假设、替代解释、支持与反证；
- 决定：继续、调整、停止或补证；
- 行动：owner、完成定义、观察窗、成功/失败门和回滚。

只看相关性时不声称因果。A/B 参数不完整时不套默认显著性、样本量或周期；参数齐全后使用产品管理 Skill 的实验脚本复算。

## 11. 交付前检查

- 是否定义了产品阶段和核心价值，而非先画看板；
- 是否只突出一个北极星，并通过反向失真检验；
- AI 质量是否进入价值定义或护栏，而非平铺成装饰层；
- 每个关键指标是否有完整定义卡；
- 是否给出最小埋点、基线建立和告警处置方法；
- 是否区分管理层、产品、质量、工程和安全视图；
- 所有示例数字是否明确为虚拟，真实目标是否有依据；
- 用户要求看板时，是否已交付并实际预览可操作原型，且验证筛选/切换、下钻、告警行动和空/错/加载态；
- 是否删除无来源的行业阈值、固定周期和通用“最佳实践”数字；
- 最终是否给出本周期主攻方向、owner 待确认项和下一步。
